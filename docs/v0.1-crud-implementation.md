# 다음 한칸 v0.1 — 실제 CRUD 연결

## 상태

**2026-09-12 구현.**

기존 화면 프로토타입의 데모 배열을 제거하고 `public.structure_items`, `public.user_focus`를 직접 읽고 쓰도록 연결했다.

## 이번 단계에서 연결한 것

- Supabase Auth 로그인/회원가입/로그아웃
- 기존 오늘한칸과 동일한 Supabase 계정 사용
- 기존 `onekan_state`는 읽거나 수정하지 않음
- `structure_items` 실제 조회
- 정체성 / 목표 / 프로젝트 / 작업 / 다음 한칸 생성
- 제목, 설명, 상위 연결, 시작일, 기한 수정
- 완료 / 보관 / 중단 / 다시 시작
- 명시적 hard delete
- 상위 삭제 시 하위 항목은 유지되고 `parent_id`만 해제
- 작업 쪼개기 → 여러 `next_step` 일괄 생성
- 쪼갠 항목 중 하나를 `user_focus.current_item_id`로 저장
- 홈의 `지금 한칸` 실제 연결
- 홈의 활성 `next_step` 목록 실제 연결
- `next_step` 완료 시 DB 트리거에 의해 focus 자동 해제
- 보관함을 실제 비활성 상태 항목으로 렌더링

## 구조 화면 탐색

오늘 확정한 구조 탐색 규칙도 함께 반영했다.

### 방향 → 행동

`정체성 → 목표 → 프로젝트 → 작업 → 다음 한칸`

- 각 항목의 `› / ⌄` 토글로 단계별 펼침/접힘
- 전체 펼치기 / 전체 접기
- 정체성 / 목표 / 프로젝트 기준 필터

### 행동 → 방향

`다음 한칸 → 작업 → 프로젝트 → 목표 → 정체성`

- 활성 `next_step`에서 시작해 `parent_id`를 거슬러 올라감
- 단계별 펼침/접힘
- 다음 한칸이 어떤 방향에서 나온 행동인지 확인하는 용도

### 로컬 저장

다음 UI 상태는 DB에 저장하지 않고 브라우저 `localStorage`에 둔다.

- 정방향 / 역방향 보기
- 펼쳐진 항목 ID
- 구조 필터

## 보안

프론트에서는 Supabase publishable key만 사용한다.

실제 행 접근은 DB RLS가 담당한다.

- `authenticated` 사용자만 신규 테이블 CRUD 가능
- `(select auth.uid()) = user_id` 정책으로 소유권 제한
- 다른 사용자의 행을 부모로 연결할 수 없음
- 다른 사용자의 `next_step`을 focus로 지정할 수 없음

`@supabase/supabase-js` CDN 의존성은 구현 시점의 안정 버전 `2.116.0`으로 고정했다.

## 검증

DB 트랜잭션에서 인증 사용자 역할로 다음 흐름을 재검증했다.

1. 정체성 생성
2. 목표 연결
3. 프로젝트 연결
4. 작업 연결
5. 다음 한칸 연결
6. `user_focus` 지정
7. 항목 수정
8. 다음 한칸 완료 처리
9. 상위 hard delete 후 하위 `parent_id` 해제
10. 전체 테스트 rollback

테스트 데이터는 실제 DB에 남기지 않았다.

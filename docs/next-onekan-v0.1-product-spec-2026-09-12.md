# 다음 한칸 v0.1 제품 기획 정리 — 2026-09-12

## 1. 제품 방향

`다음 한칸`은 일반적인 투두앱이 아니라, 큰 방향과 목표를 실제로 움직일 수 있는 가장 작은 행동까지 쪼개는 실행 설계 앱이다.

제품 한 문장:

> 큰 방향을 실제로 움직일 수 있는 `다음 한칸`까지 쪼개는 앱.

핵심 질문은 두 가지다.

- 위에서 아래로: `나는 무엇을 원하는가 → 그래서 무엇을 해야 하는가?`
- 아래에서 위로: `나는 지금 무엇을 하는가 → 그래서 이게 왜 중요한가?`

## 2. 핵심 구조

기본 계층은 5단계로 고정한다.

`정체성 → 목표 → 프로젝트 → 작업 → 다음 한칸`

예시:

- 정체성: 꾸준히 만드는 사람
- 목표: 디자인 포트폴리오 완성
- 프로젝트: 포트폴리오 웹사이트
- 작업: 메인 페이지 디자인
- 다음 한칸: 레퍼런스 사이트 3개 저장하기

### 원칙

- 모든 항목이 반드시 정체성까지 연결될 필요는 없다.
- 독립된 `다음 한칸`과 독립된 작업을 허용한다.
- 일반적인 생활 할일까지 억지로 5단계에 연결하지 않는다.
- v0.1에서는 5단계보다 더 깊은 무한 하위 구조를 만들지 않는다.
- `쪼개기`의 최종 목적은 하위 할일을 많이 만드는 것이 아니라, `지금 실제로 할 수 있는 다음 행동`을 결정하는 것이다.

## 3. 리뉴얼 오늘한칸과 역할 분리

### 리뉴얼 오늘한칸

질문: `그래서 오늘 무엇을 할 것인가?`

담당 영역:

- 일정
- 일반 할일
- 습관
- 오늘 실행
- 캘린더/시간 기반 관리

### 다음 한칸

질문: `내가 원하는 곳까지 어떻게 갈 것인가?`

담당 영역:

- 정체성
- 목표
- 프로젝트
- 작업
- 작업 쪼개기
- 다음 행동 결정

장기적으로는 `다음 한칸`에서 만든 실행 항목을 리뉴얼 오늘한칸으로 보내는 연동을 검토할 수 있다. v0.1에서는 연동을 구현하지 않는다.

## 4. 기존 오늘한칸 데이터 처리 결정

기존 Supabase 데이터는 삭제하지 않고 보존한다.

- 다른 사용자의 데이터는 자동 이전하지 않는다.
- 기존 데이터를 리뉴얼 오늘한칸으로 일괄 마이그레이션하지 않는다.
- 사용자가 필요할 때 참고할 수 있도록 레거시 데이터로 남긴다.
- 사용자는 구버전에 남아 있던 할일/습관을 텍스트로 확인한 뒤 필요한 것만 새 리뉴얼판에 직접 옮기기로 했다.
- 다음 한칸 개편 과정에서는 기존 Supabase 데이터 구조를 수정하거나 삭제하지 않는다.

## 5. v0.1 화면 구조

메인 내비게이션:

- 홈
- 구조
- 보관함
- 설정
- 전역 `+ 추가`

모바일은 하단 내비게이션, PC는 좌측 사이드바를 사용한다.

### 5.1 홈

목적: 구조 관리가 아니라 실행.

구성:

- `지금 한칸` 1개를 크게 표시
- 그다음 실행 가능한 `다음 한칸` 목록
- 각 항목에는 전체 계층 대신 짧은 경로만 표시
- 완료 토글

예:

`레퍼런스 사이트 3개 저장하기`

`포트폴리오 웹사이트 › 메인 페이지 디자인`

추후 홈 카드에는 `왜 하는 일이지?`를 펼쳐 상위 구조를 역방향으로 확인하는 기능을 검토한다.

### 5.2 구조

앱의 핵심 관리 화면.

PC:

- 좌측: 계층 트리
- 우측: 선택 항목 상세
- 마스터-디테일 방식

모바일:

- 계층 목록을 단계별로 탐색
- 선택 후 상세 화면/영역으로 이동

상단 필터:

- 전체
- 정체성
- 목표
- 프로젝트

### 5.3 상세

정체성/목표/프로젝트/작업/다음 한칸이 같은 기본 패턴을 공유한다.

공통 요소:

- 제목
- 설명
- 상위 연결
- 진행 상태
- 하위 항목
- 수정 / 보관 / 완료 / 삭제

작업 상세에서는 `이 작업 더 쪼개기` 진입점을 제공한다.

### 5.4 쪼개기

다음 한칸의 핵심 UX.

흐름:

1. 작업을 선택한다.
2. 이 일을 끝내기 위해 필요한 단계를 나눈다.
3. 여러 단계 중 `지금 가장 먼저 할 수 있는 것`을 고른다.
4. 해당 항목을 `다음 한칸`으로 지정한다.
5. 지정된 다음 한칸은 홈 실행 목록에 나타난다.

핵심은 `하위 작업 생성`이 아니라 `가장 먼저 실행할 행동 결정`이다.

### 5.5 보관함

삭제와 보관을 분리한다.

구분:

- 완료
- 보관
- 중단

필요하면 다시 시작할 수 있다.

### 5.6 설정

v0.1에서는 최소 설정만 둔다.

## 6. 구조 화면의 펼치기/접기

5단계 구조가 한꺼번에 노출되면 복잡해질 수 있으므로 단계별 토글을 사용한다.

예:

```text
⌄ 🌱 꾸준히 만드는 사람
   ⌄ 🎯 포트폴리오 완성
      › 📁 웹사이트 제작
      › 📁 개인작 정리

› 🌱 안정적으로 일하는 사람
```

원칙:

- 각 항목의 `› / ⌄` 버튼으로 바로 아래 단계만 펼치거나 접는다.
- `모두 펼치기 / 모두 접기`를 제공한다.
- 펼침 상태는 사용자가 화면을 떠났다가 돌아와도 유지하는 방향으로 한다.
- v0.1에서는 DB 저장 대신 브라우저 로컬 상태로 기억해도 된다.

## 7. 정방향 / 역방향 보기

구조 화면은 두 방향으로 탐색할 수 있게 한다.

### 정방향: 방향 → 행동

기본값.

`정체성 → 목표 → 프로젝트 → 작업 → 다음 한칸`

질문:

> 내가 원하는 방향을 이루기 위해 무엇을 해야 하지?

### 역방향: 행동 → 방향

`다음 한칸 → 작업 → 프로젝트 → 목표 → 정체성`

질문:

> 내가 지금 하는 이 행동은 왜 필요한 거지?

PC에서는 segmented toggle 형태를 우선 검토한다.

`[ 방향 → 행동 | 행동 → 방향 ]`

모바일에서는 드롭다운 또는 2-way 토글을 사용한다.

홈의 `다음 한칸` 카드에서도 `왜 하는 일이지?`를 펼쳐 상위 연결을 역방향으로 보여주는 방식을 검토한다.

## 8. 전역 추가

`+` 버튼에서 다음 항목을 만들 수 있다.

- 다음 한칸
- 작업
- 프로젝트
- 목표
- 정체성

빠르게 입력한 행동은 상위 구조 연결 없이도 저장할 수 있다.

생성 후 `어딘가에 연결할까요?` 단계에서 선택적으로 연결한다.

## 9. v0.1에서 만들지 않는 것

다음 기능은 의도적으로 범위에서 제외한다.

- 캘린더
- 일정
- 습관
- 반복 작업
- 타임블럭
- 시간추적
- 통계 대시보드
- 복잡한 태그 시스템
- 협업
- 알림
- AI 자동 쪼개기
- 리뉴얼 오늘한칸 실시간 연동

핵심 쪼개기 UX가 충분히 좋아진 뒤 필요성을 다시 판단한다.

## 10. 현재 구현 상태

2026-09-12 기준 v0.1 화면 프로토타입이 `main`에 반영되어 있다.

구현됨:

- 반응형 App Shell
- PC 사이드바
- 모바일 하단 내비게이션
- 홈
- 구조
- 상세 패널
- 쪼개기 모달
- 빠른 생성 모달
- 보관함
- 설정
- 데모 데이터 기반 상호작용

아직 구현하지 않음:

- Supabase CRUD
- 실제 로그인/계정 연결
- 실제 생성/수정/삭제
- 실제 진행률 계산
- 보관/복구 저장
- 단계별 펼침/접힘 상태 저장
- 정방향/역방향 보기

## 11. 다음 단계

화면 구조 다음 단계는 `데이터 모델 설계`다.

구현 전에 아래를 먼저 확정한다.

1. 정체성/목표/프로젝트/작업/다음 한칸을 별도 테이블로 둘지, 하나의 계층형 테이블로 통합할지
2. 부모-자식 연결 방식
3. 하나의 항목이 여러 상위 항목과 연결될 수 있는지
4. 상태값(진행/완료/보관/중단)
5. 다음 한칸 지정 규칙
6. 진행률 계산 방식
7. 정렬 순서
8. 펼침 상태 및 보기 방향 같은 UI 상태의 저장 위치

v0.1에서는 데이터 구조를 단순하게 유지하고, 레거시 `onekan_state` 방식처럼 앱 전체 상태를 JSON 한 덩어리로 저장하지 않는 방향을 우선 검토한다.
